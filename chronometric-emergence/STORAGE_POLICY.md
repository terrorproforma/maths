# Repository storage policy

This GitHub repository is the canonical storage location for the chronometric-emergence programme.

## Rules

1. Every self-contained research project or stage gets its own folder under [`projects/`](projects/).
2. Notes, manuscript source, verification code, machine-readable results, configuration, evidence matrices and reproducibility instructions are committed with the project.
3. Generated binary artefacts that are needed to reproduce or inspect a result are committed where repository limits permit; large reproducible outputs may instead be generated by CI from committed source and inputs.
4. Temporary notebook, sandbox or chat-session paths are never the sole canonical copy of project work.
5. Historical folders are preserved unchanged. Corrections are recorded in a later project, erratum or evidence-audit folder rather than silently rewriting provenance.
6. Current scientific status is controlled by [`frontier-evidence-v2/`](frontier-evidence-v2/) and its errata, not by the strongest wording in an older research stage.
7. Every material update must end in a Git commit with a descriptive message. Large or risky changes should use a branch and pull request before merging to `main`.

## Directory roles

- [`projects/`](projects/) — organised self-contained project sequence and current index.
- [`original-info/`](original-info/) — recovered original packages and binary artefacts, preserved for provenance.
- [`frontier-evidence-v2/`](frontier-evidence-v2/) — canonical adversarial audit, corrected calculations and present frontier decision.
- [`sources/`](sources/) — source conversation material.

A local checkout may be used for computation, but the work is not considered stored until the relevant source, inputs, results and status notes are committed here.
